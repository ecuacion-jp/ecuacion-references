housekeep-files の動作は Excel ファイル 1 枚で制御します。
Excel ファイルには以下の 4 つのシートがあります。

| シート名 | 役割 |
| --- | --- |
| 基礎情報設定 | ツール全体の基本設定（システム名など） |
| タスク設定 | 実行するファイル操作タスクの一覧 |
| パス設定 | パス変数の定義 |
| サーバ認証設定 | SFTP 接続先サーバの認証情報 |

---

## 基礎情報設定シート

キーと値のペアで記載します。

| 項目（キー） | 説明 |
| --- | --- |
| `env-name` | システム・環境を識別する名前。ログや警告メールの件名に使用される。半角英数字・ハイフン・スペース等（記号一部除く）、最大 40 文字 |

---

## タスク設定シート

ファイル操作のタスクを 1 行 1 タスクで記載します。タスクは上から順番に実行されます。

### 列一覧

| 列名 | 必須 | 説明 |
| --- | --- | --- |
| タスクID | ○ | タスクを識別する ID。半角英数字・スペース・記号（一部除く）、最大 10 文字 |
| タスク名 | ○ | タスクの名前。最大 40 文字 |
| 処理パターン日本語名 | — | 人間が読むための処理パターン名（読み取り時は無視される） |
| 処理パターン | ○ | 処理の種類。`TaskPtnEnum` の値を記載（詳細は[処理パターン](page?id=housekeep-files/task-patterns&lang=ja)参照） |
| 接続先サーバ | △ | SFTP タスク使用時に必須。サーバ認証設定シートの「サーバ名」と一致させる |
| 元パス | △ | 操作元のファイル・ディレクトリパス。`${VAR_NAME}` 形式の変数参照可。ワイルドカード（`*`, `?`）も使用可 |
| 元パスがディレクトリ | △ | `true` / `false`。元パスがディレクトリの場合は `true` |
| 元パス処理実施対象経過期間単位 | △ | 現在は `DAY` のみ対応 |
| 元パス処理実施対象経過期間値 | △ | 何日前のファイルを対象とするか（0 以上 1000 以下の整数）。`0` は経過日数に関係なく全対象 |
| 元パス存在なし時処理 | △ | 元パスが存在しない場合の処理。`IGNORE` / `WARN` / `ERROR` |
| 先パス | △ | 操作先のファイル・ディレクトリパス。`${VAR_NAME}` 形式の変数参照可（ワイルドカード不可） |
| 先パスがディレクトリ | △ | `true` / `false`。先パスがディレクトリの場合は `true`（元ファイル名のまま配置） |
| 先パス存在時上書き | △ | `true` / `false`。先パスが既に存在する場合に上書きするかどうか |
| 先パス存在時処理 | △ | 先パスが存在する場合の処理。`IGNORE` / `WARN` / `ERROR` |
| options | — | 予約項目（現在未使用） |

△ は処理パターンによって必須・禁止・任意が変わります（詳細は[処理パターン](page?id=housekeep-files/task-patterns&lang=ja)参照）。

### 元パス関連項目の入力ルール

「元パス」「元パスがディレクトリ」「元パス処理実施対象経過期間単位」「元パス処理実施対象経過期間値」「元パス存在なし時処理」の 5 項目は、
**すべて入力するか、すべて空白にするか**のどちらかである必要があります。一部だけ入力するとエラーになります。

### 先パス関連項目の入力ルール

「先パス」「先パスがディレクトリ」「先パス存在時上書き」「先パス存在時処理」の 4 項目も同様に、
**すべて入力するか、すべて空白にするか**のどちらかです。

### ワイルドカードについて

元パスにはワイルドカード（`*`, `?`）を使用できます。ワイルドカードが含まれる場合、
マッチするすべてのファイルに対してタスクが実行されます。

```
/data/logs/*.log         # .log ファイルすべて
/data/backup/202?-*.zip  # 202x 年で始まる zip ファイル
```

### 処理パターン値の設定について

「処理パターン日本語名」列は人間が読みやすいように記載する列で、ツールの読み取り時には無視されます。
ツールが参照するのは「処理パターン」列です。使用可能な値は[処理パターン](page?id=housekeep-files/task-patterns&lang=ja)を参照してください。

### 元パス存在なし時処理 / 先パス存在時処理 の値

| 値 | 動作 |
| --- | --- |
| `IGNORE` | 無視してタスクを終了する（次のタスクに進む） |
| `WARN` | 警告をログに記録して次のタスクに進む |
| `ERROR` | エラーとして例外をスローしてバッチを停止する |

---

## パス設定シート

元パス・先パスで使用するパス変数を定義します。

| 列名 | 必須 | 説明 |
| --- | --- | --- |
| パス変数名 | ○ | 変数名。大文字・数字・アンダースコアのみ（例: `BASE_DIR`, `LOG_PATH`）。最大 50 文字 |
| パス値 | ○ | 実際のパス。最大 300 文字 |

タスク設定シートのパス欄では `${BASE_DIR}` のように参照します。
パス値にはさらに別のパス変数を入れ子にすることはできません。

---

## サーバ認証設定シート

SFTP タスクを使用する場合にのみ設定が必要です。SFTP を使わない場合はシートを空のままにしてください。

| 列名 | 必須 | 説明 |
| --- | --- | --- |
| サーバ名 | ○ | サーバの識別名。タスク設定シートの「接続先サーバ」と対応させる。最大 40 文字 |
| protocol | ○ | 接続プロトコル。現在は `SFTP` のみ対応 |
| port | ○ | 接続ポート番号（0〜99999） |
| 認証方式 | ○ | `PASSWORD`（パスワード認証）/ `KEY`（公開鍵認証）/ `KERBEROS`（Kerberos 認証） |
| ユーザ名 | △ | ログインユーザ名（最大 40 文字） |
| password / passphrase | △ | パスワード、または公開鍵の passphrase（最大 30 文字） |
| 秘密鍵パス | △ | `KEY` 認証時の秘密鍵ファイルパス（最大 300 文字） |

### 認証方式ごとの入力内容

| 認証方式 | ユーザ名 | password / passphrase | 秘密鍵パス |
| --- | --- | --- | --- |
| `PASSWORD` | 必須 | パスワードを記入 | 不要 |
| `KEY` | 必須 | passphrase があれば記入 | 秘密鍵パスを記入 |
| `KERBEROS` | 不要 | 不要 | 不要 |

---

## 空行によるデータ区切り

各シートのテーブルで、途中に空行がある場合、その空行以降のデータは読み取られません。
「使わないけど残しておきたい設定」は空行の後ろに書いておくことで無視させることができます。
