このページでは、`ecuacion-tool-housekeep-db` がSQL文を組み立てる際のセキュリティ上の考慮事項について説明します。

## テーブル名・カラム名の検証

Excel設定ファイルで指定するテーブル名・カラム名（`テーブル名`、`IDカラム名`、`関連テーブル名`など）は、いずれも正規表現 `^[A-Za-z_][A-Za-z0-9_]*$`（英数字とアンダースコアのみ、数字始まり不可）でバリデーションされます。

これらの値はSQL文にクォートなしでそのまま埋め込まれますが、この制限により識別子として解釈できない文字（クォート・セミコロン・空白など）を含めることができないため、識別子経由でのSQLインジェクションは起こりません。

## 値のバインド

以下の値は、SQL文字列へのリテラル埋め込みではなく、`PreparedStatement` の `?` プレースホルダにバインドされます。

- housekeep対象レコードのID・関連テーブルの外部キー値（いずれもDBから読み戻した値）
- soft-deleteフラグ（`true` / `false`）
- 更新日時（"now"）

このため、対象テーブルに格納されている既存データの内容によってSQL文が壊れたり注入されたりすることはありません。また、PostgreSQLとMySQL/MariaDBとで文字列リテラルのエスケープ規則が異なる（後者はデフォルトでバックスラッシュがエスケープ文字として働く）といったDB方言差分も、バインドする限り意識する必要がありません。

## Excel設定ファイルの値

データ検索条件設定シートの`条件値`、および`更新者ID列の値`など、Excel設定ファイルに直接入力する値は上記の対象外です。これらは信頼できる管理者が用意する設定情報であるため、従来通りシングルクォートをエスケープした上でリテラルとしてSQL文に埋め込まれます。
