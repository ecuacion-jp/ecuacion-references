関連テーブルの処理を設定します。必要ない場合はシートを空のままにしてください。

このシートでは 2 種類の処理が設定できます。

| 処理パターン | 内部値 | 動作 |
| --- | --- | --- |
| 関連テーブル論理廃止／削除 | `DELETE` | ターゲットテーブルの ID に紐づく関連テーブルのレコードを削除してから、ターゲットテーブルを削除 |
| 削除対象テーブル論理廃止／削除のためのデータチェック | `CHECK_AND_SKIP_DELETE` | 関連テーブルにレコードが存在する場合、ターゲットテーブルの削除をスキップ |

## 列一覧

| 列名 | 必須 | 説明 |
| --- | --- | --- |
| 処理ID | ○ | housekeep DB設定 シートのタスク ID と一致させる |
| 論理廃止 / 削除（内部値） | ○ | `SOFT_DELETE` または `HARD_DELETE`。対応するタスクの設定と一致させる |
| 関連テーブル処理パターン | ○ | 表示用パターン名（「関連テーブル論理廃止／削除」または「削除対象テーブル論理廃止／削除のためのデータチェック」） |
| 関連テーブル処理パターン（内部値） | ○ | `DELETE` または `CHECK_AND_SKIP_DELETE` |
| 対象テーブルカラム名 | ○ | ターゲットテーブル（削除対象テーブル）の列名。関連テーブルと結合するキー |
| 関連テーブル名 | ○ | 関連テーブルの名前 |
| 関連テーブルIDカラム名 | ○ | 関連テーブルの ID 列（主キーまたはユニークインデックス）の名前 |
| 関連テーブルIDカラム型リテラル記号 | ○ | 関連テーブルの ID 列にクォートが必要かどうか。`(none)` または `quotes(')` |

**DELETE パターンの論理廃止設定（任意）**

関連テーブルのレコードを論理廃止する場合は以下の列も設定します。

| 列名 | 説明 |
| --- | --- |
| 削除フラグカラム名 | 関連テーブルの削除フラグ列 |
| 論理廃止：更新用timestampカラム名 | 論理廃止時に更新するタイムスタンプ列 |
| 論理廃止：更新用ユーザIDカラム名 | 論理廃止時に更新するユーザ ID 列 |
| 論理廃止：更新用ユーザIDカラム型リテラル記号 | ユーザ ID 列のクォート要否 |
| 論理廃止：更新用ユーザIDカラム値 | ユーザ ID 列にセットする値 |
