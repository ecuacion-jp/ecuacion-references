関連テーブルの処理を設定します。必要ない場合はシートを空のままにしてください。

このシートでは 2 種類の処理が設定できます。

| 処理パターン | 動作 |
| --- | --- |
| 論理廃止／削除 | ターゲットテーブルの ID に紐づく関連テーブルのレコードを削除してから、ターゲットテーブルを削除 |
| 存在チェック | 関連テーブルにレコードが存在する場合、ターゲットテーブルの削除をスキップ |

## この機能を使う場合

### 論理廃止／削除

論理廃止／削除は、本来はテーブルごとに個別に実行するのが望ましい処理です。ただし、削除要否の判断基準となる timestamp などの項目が関連テーブル自体に存在せず、関連テーブル単体では削除すべきか否かを判断できない場合があります。この機能は、そのようなケースでターゲットテーブル側の削除に連動させて関連テーブルを削除するためのものです。この性質上、関連テーブル側の timestamp カラムなどで削除条件を指定する機能は用意していません。

### 存在チェック

存在チェックは、関連テーブル側があらかじめ適切な条件で論理廃止／削除済みであることを前提とした機能です。

タスクが論理廃止の場合（housekeep DB設定 シートの「論理廃止 / 削除」列で「論理廃止」を指定した場合）は、論理廃止済みの関連レコードは「存在する」とみなされず、未廃止の関連レコードが存在する場合のみターゲットテーブルの論理廃止をスキップします。この判定のため、タスクが論理廃止の場合は「削除フラグカラム名」の設定が必須です。タスクが削除の場合は、単純にレコードの存在のみをチェックします。

## 列一覧

| 列名 | 必須 | 説明 |
| --- | --- | --- |
| 処理ID | ○ | housekeep DB設定 シートのタスク ID と一致させる |
| 関連テーブル処理パターン | ○ | 表示用パターン名（「論理廃止／削除」または「存在チェック」） |
| 対象テーブルカラム名 | ○ | ターゲットテーブル（削除対象テーブル）の列名。関連テーブルと結合するキー |
| 関連テーブル名 | ○ | 関連テーブルの名前 |
| 関連テーブルIDカラム名 | ○ | 関連テーブルの ID 列（主キーまたはユニークインデックス）の名前 |
| 関連テーブルIDカラム型リテラル記号 | ○ | 関連テーブルの ID 列にクォートが必要かどうか。`(none)` または `quotes(')` |

**論理廃止関連の設定**

以下の列は、次の場合に設定します。

- 削除フラグカラム名：タスクが論理廃止の場合、処理パターンによらず必須。論理廃止／削除 パターンでは関連テーブルの論理廃止に、存在チェック パターンでは論理廃止済みレコードを除外した存在チェックに使用します。タスクが削除の場合は任意で、論理廃止／削除 パターンで指定すると、論理廃止済み（削除フラグ = true）の関連レコードのみを削除します（存在チェック パターンでは使用されません）
- 「論理廃止：更新用〜」の各列：論理廃止／削除 パターンで関連テーブルのレコードを論理廃止する場合に任意で設定します

設定項目の詳細は、[housekeep DB設定](page?id=housekeep-db/excel-settings/housekeep-db-settings&lang=ja)の「論理廃止の場合」の設定例を参照してください（列の意味・使い方は同じです）。

| 列名 | 説明 |
| --- | --- |
| 削除フラグカラム名 | 関連テーブルの削除フラグ列 |
| 論理廃止：更新用timestampカラム名 | 論理廃止時に更新するタイムスタンプ列 |
| 論理廃止：更新用ユーザIDカラム名 | 論理廃止時に更新するユーザ ID 列 |
| 論理廃止：更新用ユーザIDカラム型リテラル記号 | ユーザ ID 列のクォート要否 |
| 論理廃止：更新用ユーザIDカラム値 | ユーザ ID 列にセットする値 |

## 設定例

### 論理廃止／削除の場合

#### 1. テスト用テーブルとデータの準備

```sql
CREATE TABLE test_table (
    num1 integer,
    char1 varchar,
    PRIMARY KEY (num1)
);

CREATE TABLE related_table (
    id integer,
    parent_id integer,
    PRIMARY KEY (id)
);

INSERT INTO test_table (num1, char1) VALUES (123, 'abc');
INSERT INTO related_table (id, parent_id) VALUES (1, 123);
```

#### 2. Excel 設定ファイルの編集

##### housekeep DB設定 シート

| 処理ID | DB接続ID | 論理廃止 / 削除 | テーブル名 | IDカラム名 | IDカラム型リテラル記号 |
| --- | --- | --- | --- | --- | --- |
| task-1 | test-conn | 削除 | test_table | num1 | (none) |

##### 関連テーブル処理設定 シート

| 処理ID | 関連テーブル処理パターン | 対象テーブルカラム名 | 関連テーブル名 | 関連テーブルIDカラム名 | 関連テーブルIDカラム型リテラル記号 |
| --- | --- | --- | --- | --- | --- |
| task-1 | 論理廃止／削除 | num1 | related_table | parent_id | (none) |

実行すると、`related_table` の `parent_id=123` のレコード（`id=1`）が先に削除され、続けて `test_table` の `num1=123` が削除されます。

### 存在チェックの場合

#### 1. テスト用テーブルとデータの準備

```sql
CREATE TABLE test_table (
    num1 integer,
    char1 varchar,
    PRIMARY KEY (num1)
);

CREATE TABLE related_table (
    id integer,
    parent_id integer,
    PRIMARY KEY (id)
);

INSERT INTO test_table (num1, char1) VALUES (123, 'abc');
INSERT INTO test_table (num1, char1) VALUES (456, 'def');
-- num1=123 にのみ関連レコードあり
INSERT INTO related_table (id, parent_id) VALUES (1, 123);
```

#### 2. Excel 設定ファイルの編集

##### housekeep DB設定 シート

| 処理ID | DB接続ID | 論理廃止 / 削除 | テーブル名 | IDカラム名 | IDカラム型リテラル記号 |
| --- | --- | --- | --- | --- | --- |
| task-1 | test-conn | 削除 | test_table | num1 | (none) |

##### 関連テーブル処理設定 シート

| 処理ID | 関連テーブル処理パターン | 対象テーブルカラム名 | 関連テーブル名 | 関連テーブルIDカラム名 | 関連テーブルIDカラム型リテラル記号 |
| --- | --- | --- | --- | --- | --- |
| task-1 | 存在チェック | num1 | related_table | parent_id | (none) |

実行すると、関連レコードが存在する `num1=123` は削除がスキップされ、関連レコードのない `num1=456` のみ削除されます。
