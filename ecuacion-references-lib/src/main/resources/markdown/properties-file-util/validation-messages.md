## Overview

The 3 `ValidationMessages` files are used for handling validation messages in Jakarta Validation.
They are primarily called automatically from within the ecuacion framework.

Unlike `getMessage()` and similar methods, internally they use `Map<String, Object>` as arguments.
This is because Jakarta Validation annotation attributes use named placeholders like `{value}`, `{min}`, `{max}`.

| File Name | Method | Fallback |
| --- | --- | --- |
| `ValidationMessages[_xxx].properties` | `getValidationMessage(...)` | None |
| `ValidationMessagesWithItemNames[_xxx].properties` | `getValidationMessageWithItemName(...)` | `ValidationMessages` |
| `ValidationMessagesPatternDescriptions[_xxx].properties` | `getValidationMessagePatternDescription(...)` | None |

Since messages are automatically generated by Jakarta Validation processing, application developers
do not explicitly retrieve messages from these files.
The cases where application developers directly interact are:

- **When overriding existing validation messages** — Define keys without `.default` in the application's files
- **When using `@PatternWithDescription`** — Define pattern descriptions in `ValidationMessagesPatternDescriptions.properties`

---

## ValidationMessages.properties

Stores messages for when validation is violated. The key is typically the fully qualified class name of the annotation + `.message`.

```properties
# ValidationMessages.properties
jp.ecuacion.lib.core.jakartavalidation.constraint.SomeAnnotation.message=\
    {0} must be between {min} and {max} characters.
```

`{min}` and `{max}` are annotation attribute placeholders (named, not `{0}` format).

---

## ValidationMessagesWithItemNames.properties

Stores validation messages where `{0}` is the item name placeholder.
The difference from `ValidationMessages.properties` is that messages contain `{0}`.
The framework replaces `{0}` with the actual item name before displaying it to the user.

```properties
# ValidationMessagesWithItemNames.properties
jp.ecuacion.lib.core.jakartavalidation.constraint.SomeAnnotation.message=\
    {0} must be between {min} and {max} characters.
```

---

## ValidationMessagesPatternDescriptions.properties

Stores end-user-friendly descriptions of regular expressions used with `@PatternWithDescription` and similar.
If a key is not found, it falls back to `ValidationMessages.properties`.

```properties
# ValidationMessagesPatternDescriptions.properties
pattern.phone-number=Phone number format (e.g., 090-1234-5678)
pattern.postal-code=Postal code format (e.g., 123-4567)
```

---

## EL Expression Support

EL (Expression Language) expressions using `${...}` can be used within property values.
Since ValidationMessages can treat annotation attributes like `{min}` and `{max}` as EL variables,
you can write calculations using attribute values.

```properties
# ValidationMessages.properties
# Example of calculating and embedding the average of min and max
jp.ecuacion.example.constraint.SomeAnnotation.message=\
    Recommended value is ${(min + max) / 2} ({min}~{max}).
```

`{min}`, `{max}` are named placeholders (resolved via Map),
while `${...}` are EL expressions (evaluated with annotation attribute values as variables).

`${...}` EL expression evaluation itself is only performed for `ValidationMessages`,
`ValidationMessagesWithItemNames`, and `ValidationMessagesPatternDescriptions`. For other file
types (`application`, `messages`, `item_names`, etc.), `${...}` is left untouched, since EL
variables (annotation attributes) are only meaningful for Jakarta Bean Validation message
interpolation.
