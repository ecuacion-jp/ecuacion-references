「各種設定」シートにはプロジェクト全体に関わる設定を記載します。
「システム共通」分類（6〜11行目）は**全項目が入力必須**で、空欄のまま読み込むとエラーになります。
そのうち新規プロジェクト作成時に必ず値を変更すべき項目と、テンプレートの初期値のまま使ってよい項目があります。
「システム共通」には他に必要な場合のみ入力する任意項目（12〜19行目）もあり、さらに「システム共通」分類外にも機能を使う場合のみ入力すればよい任意項目があります。

## 1. プロジェクトごとに必ず変更する項目（入力必須）

| 行 | 項目 | 説明 |
| --- | --- | --- |
| 7 | システム名 | プロジェクト識別名。生成ソースの親フォルダ名になる。英数字・ハイフン推奨（例: `my-project`） |
| 8 | packageの共通部分 | 生成コードの Java パッケージ共通部分（例: `jp.example.myapp`） |

## 2. 入力必須だが、通常はテンプレートの初期値のまま使う項目

これらも空欄にはできませんが、テンプレートに妥当な初期値が入っているため、特別な理由がない限り変更不要です。

| 行 | 項目 | 初期値 | 説明 |
| --- | --- | --- | --- |
| 6 | テンプレートのバージョン | テンプレートのバージョン（例: `5.0.0`） | 本 Excel ファイルのテンプレートバージョン。ダウンロードした値のまま使う |
| 9 | frameworkの種類 | `Spring Framework` | 使用するフレームワークの種類（`Spring Framework` または `jakarta EE`） |
| 10 | 文字コード | `UTF-8` | 生成ソースコードの文字コード |
| 11 | デフォルト言語 | `en` | デフォルト言語。ロケール文字列（例: `en`, `en_US`） |

## 3. 機能を使う場合のみ入力する任意項目

残りの「システム共通」項目（12〜19行目）は任意項目です。

| 行 | 項目 | 説明 |
| --- | --- | --- |
| 12〜14 | サポート言語1 / 2 / 3 | 追加サポート言語（ロケール文字列）。1, 2, 3 の順で入力する（サポート言語1が空欄でサポート言語2が入力されている状態はエラー） |
| 15 | 禁則文字 | ユーザ入力で禁止する文字（`@Pattern` によるバリデーション対象箇所でチェックされる） |
| 16 | 禁則文字パターン説明（デフォルト言語） | 禁則文字パターンの説明文（デフォルト言語）。「禁則文字」が空欄でない場合は必須 |
| 17〜19 | 禁則文字パターン説明（追加言語1 / 2 / 3） | 同説明文（各追加言語）。「禁則文字」と対応するサポート言語の両方が空欄でない場合は必須 |

「システム共通」分類外にも、機能を使う場合のみ入力すればよい任意項目があります。

| 行 | 項目 | 分類 | 説明 |
| --- | --- | --- | --- |
| 26 | グループフィルタなしのテーブル名 | 他グループを閲覧不可とする設定 | グループフィルタ列を持たないテーブル名を CSV で列挙（例: `ACC,ACC_ADMIN`）。グループ機能を使う場合のみ必須 |

### システム名

コード生成の出力先フォルダ名と、生成される `Constants.java` に埋め込まれる値です。

```java
// 例: システム名 = "my-project" の場合
public class Constants {
    public static final String SYSTEM_NAME = "my-project";
}
```

### packageの共通部分

生成されるすべての Java ソースのパッケージの共通部分です。

```
jp.example.myapp.base.entity.AccEntity
jp.example.myapp.base.bl.AccBl
...
```

### グループフィルタなしのテーブル名

グループ機能を有効にした場合（「他グループを閲覧不可とする設定」分類のカラム名を設定した場合）、すべてのテーブルはグループ列を持つか、ここに明示的に列挙されている必要があります。グループ列を持たないテーブル（認証系テーブル `ACC`, `ACC_ADMIN` など）をここに列挙します。

## 4. フレームワークの規約に基づく任意項目（未設定でその機能を無効化）

これらは「システム共通」分類外の「論理削除」・「他グループを閲覧不可とする設定」分類の項目です。上記の「システム共通」項目と異なり、テンプレートでは両分類のカラム名の「値」欄が**空欄**のまま出荷されます。空欄のままにすると対応する機能（ソフトデリート／マルチテナントグループ）自体が無効になり、組み込みのデフォルト列名はありません。設定した名前を持つカラムは全てその機能用のカラムとみなされるため、他の用途と重複しない名前を選んでください。実際に機能を使うには、
「DB項目定義」または「DB共通項目定義」シートで同名のカラムを定義する必要があります。

| 分類 | 項目 | 説明 |
| --- | --- | --- |
| 論理削除 | カラム名 | ソフトデリートのフラグ列名。空欄でソフトデリート機能を無効化 |
| 論理削除 | DataType名 | フラグ列の DataType。`BOOLEAN` 型の DataType のみ対応 |
| 論理削除 | 初期値 | ソフトデリート前の初期値（`BOOLEAN` 型 DataType の場合は例えば `false`） |
| 論理削除 | 更新値 | ソフトデリート時に書き込む値（`BOOLEAN` 型 DataType の場合は例えば `true`） |
| 他グループを閲覧不可とする設定 | カラム名 | マルチテナント用グループ列名。空欄でグループ機能を無効化 |
| 他グループを閲覧不可とする設定 | DataType名 | グループ列の DataType |

## 5. 入力必須のフレームワーク規約項目

上記2項目の「カラム名」と異なり、「楽観的排他制御」分類のカラム名は**入力必須**です。生成される全エンティティが楽観的排他制御用のバージョンカラムの存在を前提にしているため、空欄のまま読み込むとエラーになります（機能自体をオフにする手段ではありません）。「論理削除」・「他グループを閲覧不可とする設定」と異なり、テンプレートにはこの項目に `VERSION` が初期値として入力済みです。このカラムはテーブルごとに個別定義しても、共通カラムとして定義してもかまいませんが、どちらの場合もそのDataTypeの型が JPA の `@Version` で許可されている型（short・integer・long・
`Timestamp`・`DateTime`）である必要があります。

| 分類 | 項目 | デフォルト値 | 説明 |
| --- | --- | --- | --- |
| 楽観的排他制御 | カラム名 | `VERSION` | 楽観的ロック用バージョン列名 |
