「DB項目定義」シートでは、データベースのテーブルとカラムを定義します。
このシートの内容が Entity・Repository・BL 等の生成コードの基礎となります。

## 列構成

テーブル名: `テーブル7`、範囲: `A5:AK{最終行}`

| 列 | 項目 | 説明 |
| --- | --- | --- |
| A | テーブル名 | DB テーブル名（スネークケース大文字。同テーブルの行は同じ値を繰り返す） |
| B | カラム名 | DB カラム名（スネークケース大文字） |
| C | dataType | `DT_XXXX` 形式の DataType 名 |
| D | dataType 存在確認 | VLOOKUP 式による自動チェック（コピーで対応） |
| E | javaのみ | `○`=DB カラムを作成せず Entity・Record のプロパティのみ生成 |
| F | Surrogate key | `○`=このカラムがテーブルのサロゲートキー（主キー） |
| G | natural key (unique key) | `○`=このカラムがテーブルの自然キー（ユニークキー）の一部 |
| H | nullable | `○`=NULL 許可（空白=NOT NULL） |
| I | 自動採番 | `○`=値が null のとき型に応じた値を自動設定 |
| J | 強制採番 | `○`=値の有無によらず強制上書き採番 |
| K | 自動更新 | `○`=更新時に値が null のとき型に応じた値を自動設定 |
| L | 強制更新 | `○`=更新時に値の有無によらず強制上書き更新 |
| M | グループ識別項目 | `○`=グループを表す項目 |
| N | SPRING監査 | `CB` / `CD` / `LB` / `LD`（Spring Data 監査アノテーション） |
| O | 関連：種類 | `@ManyToOne` または `@OneToOne`（[リレーションシップの定義](#リレーションシップの定義)参照） |
| P | 関連：direction | `unidirectional` / `bidirectional` |
| Q | 関連：参照元変数名 | 関連元（所有側）の Java フィールド名（camelCase） |
| R | 関連：参照元オブジェクト変数名 | 生成コードで使うオブジェクト変数名の上書き指定（任意）。空欄の場合は Q 列の値を使用 |
| S | 関連：参照先テーブル | 参照先テーブル名 |
| T | 関連：参照先カラム | 参照先カラム名（通常 `ID`） |
| U | 関連：参照先変数名 | bidirectional 時の逆参照フィールド名 |
| V | 関連：eager | 空白=lazy（デフォルト）/ `○`=eager |
| W〜AF | index1〜10 | 1 から始まる連番を指定するとその順でカラムが並んだインデックスを作成 |
| AG | 備考 | コメント（生成に影響しない） |
| AH | カラム表示名（デフォルト言語） | デフォルト言語での表示名 |
| AI〜AK | カラム表示名（追加言語1〜3） | 言語別表示名 |

テーブル単位（カラム単位ではなく）の表示名は別途、「**テーブル一覧**」シートで設定します。

補足: F（Surrogate key）と G（natural key）は v5.0.0 より前のテンプレートでは「PK・UK」という単一の列（`S`・`U`
の文字コード）でしたが、v5.0.0 でそれぞれ独立した `○` 印の列に分割されました。

## テーブルの記述パターン

### 基本構造

テーブル名列（A列）が同じ値の行がまとまって 1 テーブルを構成します。

```
テーブル名   | カラム名 | DataType    | (D) | ... | F(Surr.) | G(Nat.) | H(null) | I(採番) | ...
------------|--------|------------|-----|-----|----------|---------|---------|---------|
MY_TABLE    | ID     | DT_SERIAL  | ○   |     | ○        |         |         | ○       |
MY_TABLE    | CODE   | DT_CODE    | ○   |     |          | ○       |         |         |
MY_TABLE    | NAME   | DT_ACC_NAME| ○   |     |          |         | ○       |         |
```

### サロゲートキー（全テーブル必須）

すべてのテーブルは、サロゲートキーとして指定した列をちょうど 1 つ持つ必要があり、NULL 許可にはできません。
慣例としてテーブルの先頭行に記述しますが、行の並び順自体はツールでは強制されていません。

| テーブル名 | カラム名 | dataType | F列（Surrogate key） | I列（自動採番） |
| --- | --- | --- | --- | --- |
| MY_TABLE | ID | DT_SERIAL | ○ | ○ |

- `F列=○`: サロゲートキー（PRIMARY KEY）として扱われる。F列に `○` が 0 個または 2 個以上あるテーブルは読み込みエラーになる
- `I列=○`: DB 側のシーケンスによる自動採番

### ユニークキー（Natural Key）

自然キーとなるカラムには G 列に `○` を指定します。
ユニークキーが複数ある場合は、各行に `○` を指定します。
複合ユニークキーは現在未対応です（1 テーブル内の natural key 列はすべてまとめて 1 つのユニーク制約になります）。

### NULL 許可カラム

`H列（nullable）= ○` のカラムは NULL 許可となり、生成コードで `@Nullable` アノテーションが付与されます。

---

## javaのみ（E列）

`E列=○` を指定すると DB カラムは作成されず、Entity・Record のプロパティのみ生成されます。

- `E列=○` の場合、F列（Surrogate key）以降の列への値の指定は不可です。
- 他テーブルの値を派生させて保持するなど、DB に永続化しないプロパティを定義するときに使用します。

---

## 自動採番（I列）・強制採番（J列）

### 自動採番

`I列=○` のとき、挿入時に値が null であれば型に応じた値を自動設定します。

| 型 | 採番値 |
| --- | --- |
| `int` / `long` | 1 から始まる連番 |
| Timestamp 系 | 現在日時 |
| `boolean` | `false` |
| それ以外 | エラー |

### 強制採番

`J列=○` のとき、自動採番と同様に採番しますが、**値が設定されている場合でも強制的に上書き**します。

---

## 自動更新（K列）・強制更新（L列）

### 自動更新

`K列=○` のとき、更新時に値が null であれば型に応じた値を自動設定します。

| 型 | 設定値 |
| --- | --- |
| `Timestamp` 系 | 更新時の現在日時 |
| `boolean` / `DT_FLG` | `false`（`FlgEnum.FALSE`） |
| それ以外 | エラー |

### 強制更新

`L列=○` のとき、自動更新と同様に設定しますが、**値が設定されている場合でも強制的に上書き**します。

---

## グループ識別項目（M列）

`M列=○` を指定したカラムは、グループを表す識別項目として扱われます。

各種設定でグループ識別項目のカラム名を参照できますが、グループテーブル自身のキー（例: `GROUP.ID`）はグループ列に設定した名前ではなく `ID` と命名されます。この `ID` を「グループの識別項目」として同様に扱いたい場合に `M列=○` を指定します。通常は 1 システムにつき 1 カラムのみ指定します。

---

## SPRING監査（N列）

Spring Data の監査アノテーションを付与します。

| 値 | アノテーション | 内容 |
| --- | --- | --- |
| `CB` | `@CreatedBy` | 作成者 |
| `CD` | `@CreatedDate` | 作成日時 |
| `LB` | `@LastModifiedBy` | 最終更新者 |
| `LD` | `@LastModifiedDate` | 最終更新日時 |

---

## リレーションシップの定義

テーブル間のリレーションシップは O〜V 列で定義します。

O列（関連：種類）に入力できるのは `@ManyToOne` または `@OneToOne` のみです。`@OneToMany` を直接入力することはなく、`bidirectional` な `@ManyToOne` の参照先テーブル側に自動生成されます（下記参照）。ワークブック内の「FK種類」参照シートにもこの 2 種類の関連のみが掲載されており、"多" 側からの一対多・多対多の関連はフレームワークでは対応していません。

### @ManyToOne（最も一般的な外部キー）

```
テーブル名 | カラム名  | dataType  | ... | O列           | P列             | Q列      | R列 | S列          | T列 | U列          | V列 |
---------|--------|---------|-----|--------------|----------------|---------|-----|-------------|-----|--------------|-----|
MY_TABLE  | GROUP_ID | DT_SERIAL | ... | @ManyToOne   | unidirectional | groupVar |     | GROUP_TABLE | ID  |              |     |
```

- `@ManyToOne`: 多対一（外部キーがあるテーブル側に記述）
- `unidirectional`: 一方向のみ（参照元→参照先）。ほとんどのケースでこれを使用

生成される Entity コード（抜粋）:

```java
@ManyToOne
@JoinColumn(name = "GROUP_ID")
private GroupEntity groupVar;
```

### @ManyToOne（bidirectional）

逆方向からも参照する場合は `bidirectional` を使用し、`U列` に逆参照フィールド名を指定します。

```
... | @ManyToOne | bidirectional | parentVar | | PARENT_TABLE | ID | childListVar | |
```

参照先（PARENT_TABLE）側の Entity に以下が生成されます:

```java
@OneToMany(mappedBy = "parentVar")
private List<ChildEntity> childListVar;
```

### 関連：参照元オブジェクト変数名（R列）

任意項目です。指定した場合、生成コードで使用するオブジェクト変数名がこの値で上書きされます。空欄の場合は
Q列（関連：参照元変数名）の値がそのまま使われます。

### @OneToOne

1 対 1 のリレーションシップ。指定方法は `@ManyToOne` と同様です。

### 関連：eager（V列）

`V列` が空白のとき lazy（デフォルト）、`○` のとき eager フェッチになります。

DB 構造上の上位（親）Entity を参照しており、かつ `unidirectional` の場合は eager でも構いません。
自 Entity への参照や他 Entity を介した循環参照が発生しうる場合は lazy を使用してください。

## インデックス（W〜AF列）

W〜AF 列（index1〜10）に 1 から始まる整数を指定すると、その番号の順でカラムを並べたインデックスが作成されます。

例: `MY_TABLE` に `(COL_A, COL_B)` の複合インデックスを作成する場合:

| カラム名 | W列（index1） | X列（index2） |
| --- | --- | --- |
| COL_A | 1 | |
| COL_B | 2 | |

複数のインデックスを定義する場合は、index2（X列）以降に同様に記述します。

---

## dataType 存在確認列（D列）の VLOOKUP 式

D 列は dataType 定義シートに DataType が存在するかを自動チェックする列です。
値が `×` の場合は DataType が未定義なのでエラーになります。

テーブル内での式（コピーで自動設定）:

```
=IF(NOT(ISNA(VLOOKUP(テーブル7[[#This Row],[dataType]], dataType定義!A:A, 1,FALSE))), "○", "×")
```

テーブル範囲外の行に追加した場合は、セル参照式に変更します:

```
=IF(NOT(ISNA(VLOOKUP(C{行番号}, dataType定義!A:A, 1,FALSE))), "○", "×")
```

## DB共通項目定義シート

「**DB共通項目定義**」シートでは、DB項目定義でテーブルごとに同じカラムを繰り返し定義する代わりに、**全テーブル**に自動的に付与されるカラムを定義します。列構成は上記のDB項目定義とまったく同じです（A〜AK列）。唯一の違いは、
A列（テーブル名）を空欄のままにする点です。特定の1テーブルではなく、全テーブルに適用されるためです。

監査カラム（作成者・作成日時・更新者・更新日時）、ソフトデリートフラグ、楽観的排他制御用バージョンカラムといった横断的なカラムは、この形で定義するのが慣例です。これらの機能を名前でどう有効化するかは
[各種設定シート](page?id=excel-format/general-settings&lang=ja) を参照してください。実際の使用例は
[qiita-data-viewer の `excel-format/`](https://github.com/ecuacion-jp/qiita-data-viewer/tree/main/excel-format)
を参照してください。

## ecuacion-splib が必要とする認証系テーブルについて

ブランクテンプレートの「DB項目定義」シートは空の状態で配布されており、`ecuacion-splib` を使うプロジェクトに必要な認証系テーブル（`ACC`、`ACC_ADMIN` 等）はあらかじめ定義されていません。これらを含む記入例については、
実プロジェクトの Excel ファイル（例:
[qiita-data-viewer の `excel-format/`](https://github.com/ecuacion-jp/qiita-data-viewer/tree/main/excel-format)）を参照してください。
